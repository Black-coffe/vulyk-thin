# Тонкий VULYK: что останется, что уйдёт, сколько стоит (исследование)

**Дата:** 2026-11-22 · **Бриф:** `brief.md` рядом · **Тип:** исследование, без сборки и без совета.
**Как собрано:** я сам замерил размеры и затраты. Три агента на Opus разобрали код по файлам (`scripts/` и
`install.sh`, хуки, driver, тесты, команды). Ещё один агент проверил возможности Claude Code по официальной
документации (code.claude.com, страницы прочитаны 2026-11-22, ссылки внизу). Размеры «после» — это **оценки**,
погрешность ±30-50%. Код я не переписывал и ничего не прогонял.

## Итог в одной фразе

Платформы — не корень проблемы, а следствие. VULYK везёт в каждый проект свою программу: ~52 тыс. строк кода и
тестов против ~1,9 тыс. строк инструкций. Тонкий VULYK — это ~1-1,5 тыс. строк: инструкции, встроенные механизмы
Claude Code и 3-4 маленьких скрипта. Распространяется он как плагин, без установщика и без слияний при обновлении.
Плата за это — жёсткие механические гарантии превращаются в правила, которые модель выполняет, но не доказывает.

## 1. Почему другие скиллы работают на любой ОС, а VULYK нет

Обычный скилл — это текст для модели. Файлы он читает и правит встроенными инструментами Claude Code (Read, Edit,
Grep), а их уже сделали кроссплатформенными. Своей программы у такого скилла нет, поэтому тестировать под каждую ОС
нечего.

VULYK — наоборот: это программа на bash и Python, а инструкции у неё лишь сбоку.

| Что | Строк сейчас |
|---|---|
| Код, который ставится в каждый улей (`scripts/`, `install.sh`, хуки, driver) | ~27 300 |
| Тесты этого кода | ~24 800 |
| Инструкции (команды, агенты) | ~1 900 |
| Из них один `scripts/cycle.sh` | 6 219 (242 функции, 91 строка про CR) |

Всё платформенное (CR-байты, медленный Git Bash, bash 3.2 на маке, Python из Microsoft Store, WSL-раннер)
напрямую занимает ~1,5-2 тыс. строк. Но этот налог платит каждая из остальных строк: любую из них надо проверить на
трёх ОС.

**Если просто переписать всё на один язык** (Python или Node), уйдут только эти ~2 тыс. строк обходов. Останутся
~50 тыс. строк и весь процесс: волны, запечатанные тесты, гейты, суд, раунды. А стоит дорого именно процесс.

## 3. Разбор по частям: что куда идёт

Обозначения: **И** — становится текстом инструкции; **В** — заменяется встроенным механизмом Claude Code;
**С** — остаётся маленьким скриптом; **У** — убирается.

| Часть | Строк сейчас | Куда | Строк после |

| Сторож слов владельца (`owner-guard.sh`) | 1 694 | В: plan mode, AskUserQuestion, правила ask | 0-30 |
| Сторож суда (`court-guard.sh`) | 967 | В: ограничение инструментов агента и worktree | 0 |

| **Всего** | **~52 000** | | **~1 000-1 500** |

Что остаётся ядром (в нём и есть ценность):

- `/plan` — короткий бриф с твоими словами, истории, план. Одобряешь через plan mode или AskUserQuestion.
- `/build` — сборка своими руками или параллельными worker'ами, каждый в своём worktree.
- `/review` — независимое ревью **другой моделью**; слепое место видит только бриф.
- `/ship` — локальное слияние и печать команды публикации. Публикация, как и сейчас, только по твоему слову.
- Карточки дефектов остаются как правила с `paths:`. Их проверки переезжают в CI проекта там, где это код.

## 4. Что теряется: честно

1. **Печать красного теста.** Сейчас скрипт доказывает, что тест был красным до кода. Останется правило: «сначала
   тест, покажи его падение». Модель может его нарушить.
2. **Гейты, которые нельзя обойти.** Тонкий сторож ловит честные ошибки, а не обходы через `bash -c`, переменные
   или алиасы. Документация Claude Code прямо пишет, что правила для Bash — «не граница безопасности»: `git -C .
   push` проходит мимо правила `git push`. Для жёсткой границы нужен sandbox, а на родном Windows его нет (только
   WSL2, macOS, Linux).
3. **Доказательство твоих слов.** Сейчас хук сверяет запись одобрения с транскриптом. Останутся AskUserQuestion
   и правило `ask` на запись одобрения в `plan.md`, плюс маленький хук. **На plan mode опираться нельзя:** в твоих
   глобальных настройках стоит `bypassPermissions`, а документация (одна страница, permission-modes) говорит, что
   в таком режиме блоки plan mode в терминале не держат; правила `ask` и `deny` держат. Замечание Fable.
4. **Доказательство слепоты судьи.** Останутся отдельный worktree с одним брифом и ограниченные инструменты.
5. **Твой Закон 6** («проверка, которая только предупреждает, — не проверка»). В тонком VULYK большинство карточек
   станет текстом-правилом. Механическая проверка останется только там, где её можно положить в тесты или CI
   самого проекта. Это прямой отказ от части закона, его надо решить явно.
6. **Самонаблюдение:** телеметрия, недельная эволюция, затраты по спекам.
7. **Ограничения плагина** (по документации): `CLAUDE.md` внутри плагина не загружается, поэтому конституцию
   пишут скиллы или короткий блок в `CLAUDE.md` улья. `settings.json` с правами плагин, судя по документации,
   не переносит (**не подтверждено**), значит права пишет bootstrap один раз. Каждый участник проекта ставит
   плагин сам одной командой.

Секреты и потеря данных **не теряются**: `redact.sh` (~60 строк), тонкий сторож git (~80 строк: не даёт выкинуть
незакоммиченную работу), deny на force-push и `--tags`, `leak-check` в репо VULYK.

## 5. Что остаётся платформенным

Почти ничего. Хуки на Windows идут через Git Bash, а без него через PowerShell, где «могут падать» (документация).
Хук в форме `node` + аргументы документирован как работающий везде, но требует установленного node. Для 1-2
оставшихся хуков надо выбрать: простой bash (Git Bash уже стоит у всех, кто пользуется Bash-инструментом) или
node. Хук на Python — **не подтверждён** документацией.

## 6. Как перевести ульи

15 зарегистрированных ульев. Два из них канарейки, остальные держатся до 25.11 из-за незакоммиченной работы или
чужих веток.

1. В каждом улье лежат файлы фреймворка (их перечисляет манифест `install.sh`) и данные: `docs/specs`,
   `docs/defects`, `memory/`, хост-часть `CLAUDE.md`. **Данные остаются как есть.**
2. Разовая команда миграции (это инструкция, не скрипт-установщик):
   - удалить файлы фреймворка, которые совпадают с манифестом;
   - **показать тебе отличия** там, где улей их правил (в одном улье есть свои патчи сторожей);
   - убрать проводку хуков из `settings.json` и поставить плагин;
   - оставить хост-часть `CLAUDE.md` целиком (твоё правило) и заменить только блок конституции на короткий.
3. Сначала канарейки, потом свободные ульи, занятые — когда освободятся. Один чистый улей — ~0,5-1 млн токенов и
   15-30 минут. **Но чистых только 7.** 8 отложенных стоят на версиях от 0.11 до 0.54, в них от 1 до 57
   незакоммиченных файлов. В одном нет манифеста установки, а в другом идёт спека с невыполненными историями.
   Каждый такой улей — отдельный разбор (проверка Fable). Переезд каждого улья — один коммит, который можно откатить.
4. Старые спеки в `docs/specs` остаются архивом. Новый VULYK их не исполняет, только читает.

## 7. Сколько стоит переписать: оценка

Сравниваю не с текущими спеками, а с тем, что пишется: ~1 тыс. строк текста и ~350 строк скриптов, своими руками,
без гейтов и без судов над самим собой.

| Шаг | Оценка |
|---|---|
| Ядро: 4 команды, 4-5 агентов, плагин, marketplace | 1-2 сессии, ~5-10 млн взвешенных |
| Тонкий сторож git, redact, scope-check и их ~200 строк тестов | 1 сессия, ~2-4 млн |
| Одно ревью другой моделью (Fable) и одна настоящая спека в одном улье, которым ты пользуешься | ~3-6 млн |
| Миграция 15 ульев (7 чистых, 8 с разбором) | ~10-20 млн, растянуто по свободным дням |
| **Всего** | **~20-40 млн взвешенных, 3-5 сессий плюс миграция ульев** |

Первая версия таблицы была вдвое ниже. Fable её поправила: сольные сессии в этом репо стоят 4,7-11 млн каждая,
и 15 ульев по 0,5-1 млн — это уже 7,5-15 млн, даже если все они чистые. Вывод от этого не меняется: это цена
одной нынешней спеки, но заплаченная один раз.

**Публичная сторона не оценена.** Сколько людей сидит на публичной 0.54.0, я не знаю: наружу не ходил. Если
заморозить, они остаются на 0.54.0, а ~41 млн работы над 0.55 так и не будет опубликовано.

Для сравнения: одна текущая спека стоит 20-40 млн. Главное отличие в дальнейшем: обновление тонкого VULYK —
это правка md-файлов и `plugin update`, без прогона 25 тыс. строк тестов на трёх ОС. Цифры прикинуты по аналогии
с прошлыми спеками и **не замерены**.

## 8. Варианты

1. **Тонкий VULYK как плагин, с нуля, руками, со шлюзом, а старый заморозить (рекомендую; Fable согласна, с
   поправкой про шлюз).** Порядок:
   - новый репо;
   - **одна настоящая спека в одном твоём улье**;
   - только потом переезд остальных ульев и публичная major-версия.

   До первой строки кода надо решить две вещи:
   - **Закон 6:** какие классы ошибок всё же получают механическую проверку;
   - **жёсткий потолок размера:** например, ≤1 500 строк и ≤4 скрипта.

   Главный риск — **отрастание** (мнение Fable). Каждая первая авария тонкого цикла по Закону 6 получит свою
   механическую проверку, и через пару месяцев он снова станет тяжёлым. Потолок и ограниченный Закон 6 держат это.

   Остальное:
   - Старый VULYK замирает на 0.55.0-dev.3: никаких 0.55/0.56 публикаций, только критичные починки, пока ульи не
     переедут. speed-1120 не сливается.
   - Новый пишется как отдельный маленький пакет по разделу 3, не через цикл VULYK (иначе снова суды над собой).
   - Для публичного репо это новая major-версия: те, кто сидит на 0.54.0, получают инструкцию переезда.
   - *Минус:* теряются гарантии из раздела 4. Две-четыре сессии работы, плюс миграция. Публичные пользователи
     получат несовместимый переход.
2. **Только заморозить, ничего не переписывать.** Дешевле всего сейчас. *Минус:* каждый улей продолжает таскать
   ~52 тыс. строк, 13 хуков на каждом шаге и тяжёлый цикл. Любая починка снова стоит суток.
3. **Тонкий VULYK, но поэтапно внутри текущего репо** (сначала плагин и установка, потом вырезать `cycle.sh`).
   *Минус:* каждый этап снова идёт через старые гейты и тесты, а это дорого. Переходное время, когда живы оба.
4. **Переписать ту же механику на один язык** (Python/Node). *Минус:* уходят ~2 тыс. строк обходов, но ~50 тыс.
   и весь процесс остаются. Цену это почти не меняет. Не рекомендую.

## 9. Что не проверено

- Размеры «после» — оценки агентов по заголовкам и счёту строк, без переписывания.
- Перенос `settings.json` в плагине и хуки на Python — нет в документации.
- `isolation: worktree` у агента есть в документации, но в этой сборке Claude Code я его не пробовал.
- Насколько тонкий цикл без печатей держит качество — неизвестно, пока его не прогнать на реальной спеке в одном
  улье. Это и есть главный риск варианта 1.
